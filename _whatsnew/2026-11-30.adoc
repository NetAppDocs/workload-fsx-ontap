=== New recommendations for SAP HANA workloads in the well-architected analysis
Workload Factory now includes the following SAP HANA configurations in the well-architected analysis for FSx for ONTAP file systems:

* *FSx for ONTAP backups for SAP HANA*: recommends disabling automatic FSx for ONTAP backups for SAP HANA and using application-aware backups instead.
* *Ransomware protection for SAP HANA*: recommends disabling ARP/AI on SAP HANA data and log volumes and protecting them with SnapCenter tamperproof snapshots.
* *Single Availability Zone deployment*: recommends placing SAP HANA data and log volumes on a Single-AZ file system.
* *Dedicated storage VM for SAP HANA*: recommends using a storage VM dedicated to SAP HANA.
* *Separate storage VMs for data and log volumes*: recommends serving SAP HANA data and log volumes from separate storage VMs.
* *Dedicated volumes*: recommends separate volumes for SAP HANA data, log, and shared.
* *Volume style*: recommends FlexVol volumes for SAP HANA data, log, and shared.
* *NFS TCP max transfer size*: recommends setting the NFS TCP max transfer size to 262144 on storage VMs that serve SAP HANA.
* *Subnet placement*: recommends deploying the EC2 instance that runs SAP HANA in the same subnet as the file system that holds the volume.

=== New recommendations for Kubernetes workloads in the well-architected analysis
Workload Factory now includes the following Kubernetes configurations in the well-architected analysis for FSx for ONTAP file systems:

* *Use Trident for Kubernetes persistent volumes*: recommends provisioning Kubernetes persistent volumes with NetApp Trident so Kubernetes manages the full volume lifecycle.
* *Trident provisioning model*: recommends using Trident NAS Economy provisioning for large-scale Kubernetes environments.
* *Volume count*: recommends reducing the number of volumes on a file system before it reaches its volume limit, because Kubernetes can't create new persistent volumes after the limit is reached.

=== New recommendations for storage VM name services
* *DNS and LDAP server redundancy*: recommends at least two DNS servers on storage VMs that use DNS, and at least two LDAP servers on storage VMs that use LDAP. A single server can block name resolution, domain authentication, or NFS access.

=== Enhancements to existing well-architected recommendations
* *Application-consistent snapshots*: now includes SAP HANA data volumes. Protect them with the SnapCenter plug-in for SAP HANA or SAP HANA data snapshots.
* *Cold data tiering*: now recommends the None tiering policy for SAP HANA data, log, and shared volumes so active database data stays on high-performance storage.
* *Ransomware protection (ARP/AI)*: no longer applies to SAP HANA data and log volumes. SAP HANA has its own recommendation.
* *Volume backups*: recommendation now describes a centrally managed, automated backup and retention strategy with FSx for ONTAP backup.
* *Snapshot expiration*: for Kubernetes volume snapshots, delete the VolumeSnapshot in Kubernetes so Kubernetes and the storage stay in sync.
* *Inactive NAS volumes* and *Inactive block devices*: for Kubernetes persistent volumes, archive the data to the capacity pool tier or remove the persistent volumes in Kubernetes.
* *Volume capacity headroom*: for volumes that back Kubernetes persistent volumes, expand the persistent volume claim or use a Trident Autogrow policy instead of resizing the volume on the storage. The 80% threshold is unchanged.
