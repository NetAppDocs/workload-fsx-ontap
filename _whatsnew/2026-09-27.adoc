=== Expanded workload tagging discovery for AWS services

Workload Factory now detects more AWS services for workload tagging, expanding support for resources that can be tagged. It can now find Amazon EKS and Amazon WorkSpaces resources and include them in the tagging system so they are available for tagging.

=== Cross-region host-to-storage relationship discovery

Workload Factory now supports finding connections between hosts and storage across multiple AWS regions as part of the workload tagging service. It can identify and link hosts and storage resources across regions, including mapping IP addresses between regions, so host-to-storage relationships are tagged and classified correctly.

=== Improved workload and host identification accuracy

Workload Factory now more accurately identifies and classifies workloads and hosts in the workload tagging service. Updated detection methods reduce misclassification and provide more accurate tagging and classification results.

=== Customer-managed Bedrock support for classification

Workload Factory now lets customers use their own Amazon Bedrock setup for workload tagging classification. Customers can provide their own Bedrock endpoint and credentials so classification requests run through their own Bedrock configuration.

=== Improved file system visibility in the interface

Workload Factory now gives you a clearer view of your file systems in the interface. You can see SSD capacity and usage trends, workload summaries, and detailed configuration information directly from the file system overview.
