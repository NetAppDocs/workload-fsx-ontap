=== New recommendations for storage VM name services
Workload Factory now includes the following recommendations for storage VM name services in the well-architected analysis:

*DNS and LDAP server redundancy*: Recommends at least two DNS servers on storage VMs that use DNS, and at least two LDAP servers on storage VMs that use LDAP. A single server failure can block name resolution, domain authentication, or NFS access.

=== Volumes explorer enhancements

==== New Volumes explorer table columns
The Volumes explorer table includes the following new columns:

* *Logical used size*: shows the space that clients see as used, before storage efficiency savings. This column appears by default.
* *Junction path*: shows the junction path for a volume.

==== Manage mount points in Volumes explorer
You can now manage where volumes are mounted in a storage VM namespace directly from Volumes explorer. Select *Manage mount points* from the *Advanced* menu for a volume to view the storage VM namespace as a tree, then mount, unmount, or change the mount point (junction path) for the volume. Workload Factory checks dependencies before it unmounts a volume. You can't unmount a volume that has other volumes mounted under it, and you get a warning when the volume has SMB shares. 

link:https://docs.netapp.com/us-en/workload-fsx-ontap/manage-volume-settings.html[Learn how to manage mount points]

==== Nested junction paths for new volumes
When you create a volume, you can now enter a nested junction path, such as `/test1/test2`, in the *Advanced configuration* section. 

link:https://docs.netapp.com/us-en/workload-fsx-ontap/create-volume.html[Learn how to create a volume]
=== Custom rules
Custom rules, available from *Well-architected* > *Custom rules*, let you start a rule from a well-architected configuration and receive a notification when a scheduled run finishes.

==== Customize a well-architected configuration as a custom rule

You can start a custom rule from a well-architected configuration so that you can apply your own threshold or scope while the original best practice stays in place. Workload Factory opens Custom rules with an editable prompt based on that configuration. The rule starts as a draft, and its description states which configuration it is based on. link:https://docs.netapp.com/us-en/workload-fsx-ontap/improve-configurations.html[Learn more about customizing a well-architected configuration]

==== Receive notifications for scheduled custom rule runs

Turn on notifications for a scheduled custom rule to get results without signing in to Workload Factory. You can receive notifications after every scheduled run or only when a run fails or partially succeeds. Notifications are sent through the channels you already set up. Manual tests do not send notifications. link:https://docs.netapp.com/us-en/workload-fsx-ontap/manage-custom-rules.html[Learn more about notifications for scheduled custom rules]
