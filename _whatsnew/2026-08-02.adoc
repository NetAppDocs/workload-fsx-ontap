=== New well-architected dashboard available for all FSx for ONTAP systems
The well-architected analysis is now available for FSx for ONTAP file systems from the new well-architected dashboard in NetApp Workload Factory. The new dashboard provides a centralized view of all your file systems across accounts and regions and their configurations in one place. A popup notification appears when you visit the *Well-architected* tab from a file system. Access the new dashboard by selecting *Well-architected* from the left navigation menu in Workload Factory. 

You can still access the well-architected analysis for a specific file system and from the *Well-architected* menu option in Storage. 

=== New widgets added to the Storage dashboard

The Storage dashboard now includes two new widgets to help you understand how you use storage and find ways to optimize it.

* *Top discovered workloads*
Shows workload data found by the tagging service across your environment. View workloads with a confidence score above 80% that include associated FSx resources, such as volumes and block devices. Each workload shows its name, number of resources, provisioned capacity, and used capacity. Sort by resource count (default), provisioned capacity, or used capacity to quickly identify your largest workloads and understand storage usage patterns.

* *AI-powered insights and observations*
Shows AI-generated insights for your managed assets. The widget reviews your estate data within the selected scope and highlights the top three findings in key areas, including capacity, performance, data protection, replication, cost savings, and storage trends.

Each insight includes a summary, detailed findings, and recommended actions. Expand an insight to see more details and prioritize issues based on severity, performance improvements, and cost-saving opportunities.

=== Workload tagging

==== AWS Systems Manager integration for workload tagging

The workload tagging service now works with AWS Systems Manager to add more details to host inventory data. Workload Factory can now collect and process SSM inventory information to better identify and classify workloads. AWS SSM attributes are also included in the tagging process to improve workload discovery accuracy.

Every volume-related configuration in the well-architected dashboard now includes the *Workload* column in the resource table. This column shows the workload that Workload Factory associates with each volume.

=== Workload tagging and AI features

Workloads are not tagged when an administrator disables AI features. If AI features are turned off in your Workload Factory account settings, the tagging service will not identify or classify workloads on your storage resources.

link:https://docs.netapp.com/us-en/workload-setup-admin/manage-genai-features.html[Learn about AI administration^].

=== Explore savings snapshot calculation improvement    
Explore savings now uses a consistent snapshot-capacity calculation, so FSx for ONTAP savings estimates correctly account for the additional snapshot capacity pool requirement.

link:https://docs.netapp.com/us-en/workload-fsx-ontap/explore-savings.html[Explore savings for your storage environments on Amazon Elastic Block Store, FSx for Windows File Server, and Elastic File System.]

==== Export replication delay data to CSV

You can now export replication delay data to a CSV file to analyze the data in a spreadsheet and share it with others.

=== S3 access point events

You can now send S3 access point events to the SNS topic on a set schedule. Each update includes all events that have occurred since the last update. 

To set up notifications for S3 events, link:https://docs.netapp.com/us-en/workload-fsx-ontap/edit-s3-access-points.html[edit S3 access points] and select *Send S3 events by SNS* under the *Journal table* section.
