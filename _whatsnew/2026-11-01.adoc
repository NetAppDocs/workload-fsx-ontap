=== Initiator group diagram enhancements    
The diagram that displays initiator groups for block devices on the Manage Client Access page now includes more details for hosts. When you hover over a host in the diagram, host details appear, including the host name, instance ID, workload type, region, and iSCSI Qualified Name (IQN).

=== Email enhancement for well-architected issues
The new email design provides more details and context for configuration issues detected by Workload Factory. The email includes the number of analyzed resources and out of those how many are warning and critical issues and what they are. You'll find a link to the FSx for ONTAP well-architected dashboard to make it easy for you to address issues right away. 

=== Well-architected dashboard enhancements

==== Workload and workload category filters
You can now filter the well-architected dashboard by workload and workload category. This helps you focus on the configurations that are most relevant to your workloads.

==== New recommendations in the well-architected analysis
Workload Factory now includes the following configurations in the well-architected analysis for FSx for ONTAP file systems: 

* *Connect host to failover node*: checks whether hosts are connected to the failover node in an active-passive FSx for ONTAP file system for reliability.
* *Connect host to preferred node*: checks whether hosts are connected to their block devices using the preferred node for performance efficiency.
* *QoS configuration*: checks whether Kubernetes persistent volumes are protected with an ONTAP QoS policy for performance efficiency.
* *Dedicated Kubernetes storage VM*: checks whether the file system is using a dedicated storage VM for Kubernetes workloads to improve isolation and simplify storage management.
* *SAP HANA snapshot policy*: checks whether the snapshot policy is set to "None" for SAP HANA volumes to lower storage costs and improve performance for active database data.
* *ARP/AI multi-device detection gap*: ARP/AI provides full protection coverage when a volume has only one block device attached to it. If a volume has multiple block devices attached, Workload Factory moves the block devices to new volumes so that each volume has only one block device. 
* *Delete unnecessary clones*: checks whether there are any volume clones older than 30 days that can be deleted to optimize storage usage and reduce costs.
* *Match igroup OS to host*: checks whether the operating system of the initiator group (igroup) matches the host's operating system to prevent I/O or performance issues.

=== Cost improvements

==== Cost forecasting
You can now forecast costs for your FSx for ONTAP file systems using the cost forecasting feature. This helps you plan your budget and optimize your resources effectively.

==== AWS Cost and Usage Reports (CUR)
Workload Factory now uses AWS Cost and Usage Reports (CUR) instead of AWS Cost Explorer toprovide detailed billing records delivered to customer-owned S3 buckets. CUR offers better cost granularity  and serves as the foundation for advanced FinOps, chargeback, and cost allocation use cases.

Workload Factory provides enhanced guidance within the user interface for migrating storage VMs. This includes step-by-step instructions and a test run before committing the migration to production.
